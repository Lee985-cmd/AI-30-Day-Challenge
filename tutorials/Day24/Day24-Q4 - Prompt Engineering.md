# Day24-Q4 - Prompt Engineering

## 🎨 什么是 Prompt Engineering?

**定义：**
Prompt Engineering 是设计和优化输入提示的艺术和科学，目的是让 AI 模型生成更好的输出。

**重要性：**
```
同样的模型，不同的 prompt:

差 prompt: "写点什么"
→ 输出: 随机、不相关

好 prompt: "写一首关于春天的五言绝句"
→ 输出: 符合要求的诗歌

差距: 天壤之别!
```

## 📚 Prompt Engineering 的核心原则

### 1. 明确具体 (Be Specific)

```python
"""
❌ 模糊的 prompt:
"写一篇文章"

✅ 具体的 prompt:
"写一篇 500 字的科普文章，介绍人工智能在医疗领域的应用，
面向普通读者，使用通俗易懂的语言，包含 3 个实际案例"

为什么好?
- 明确了主题: AI + 医疗
- 明确了长度: 500 字
- 明确了受众: 普通读者
- 明确了风格: 通俗易懂
- 明确了结构: 3 个案例
"""
```

**对比实验：**
```
测试 1: 模糊 prompt
Prompt: "介绍一下巴黎"

输出: 
"巴黎是法国的首都..." (可能太简短或太详细)

测试 2: 具体 prompt
Prompt: "用 100 字介绍巴黎的主要旅游景点，列出 top 3"

输出:
"巴黎三大景点:
1. 埃菲尔铁塔 - 标志性建筑
2. 卢浮宫 - 世界最大博物馆
3. 巴黎圣母院 - 哥特式建筑杰作"

结论: 具体的 prompt 产生更可预测、更有用的输出
```

### 2. 提供上下文 (Provide Context)

```python
"""
❌ 缺少上下文:
"怎么解决这个问题?"

✅ 提供上下文:
"我在 Python 中遇到一个错误:
代码: print(x)
错误: NameError: name 'x' is not defined
请问怎么解决?"

为什么好?
- 说明了编程语言
- 提供了代码
- 给出了错误信息
- AI 能给出精确的解决方案
"""
```

**上下文的重要性：**
```
场景: 用户问"它多少钱?"

没有上下文:
AI: "什么的价格?"

有上下文:
用户: "我想买 iPhone 15"
用户: "它多少钱?"
AI: "iPhone 15 的起售价是 799 美元"
```

### 3. 指定格式 (Specify Format)

```python
"""
❌ 不指定格式:
"列出编程语言的优点"

✅ 指定格式:
"用 bullet points 列出 Python 的 5 个主要优点，
每个优点不超过 20 字"

输出:
• 语法简洁易读
• 丰富的第三方库
• 跨平台兼容性好
• 强大的社区支持
• 适合多种应用场景

其他格式示例:
- JSON 格式
- CSV 格式
- Markdown 表格
- 编号列表
- 特定模板
"""
```

**格式示例：**
```python
# JSON 格式
prompt = """
提取以下文本中的人名和年龄，以 JSON 格式输出:
"张三今年 25 岁，李四 30 岁"

期望输出:
{
  "people": [
    {"name": "张三", "age": 25},
    {"name": "李四", "age": 30}
  ]
}
"""

# 表格格式
prompt = """
比较 Python、Java、C++ 三种语言，
用 Markdown 表格展示，包含: 语言、类型、用途、难度
"""
```

### 4. 设定角色 (Set Role)

```python
"""
❌ 无角色:
"解释量子计算"

✅ 设定角色:
"你是一位物理学教授，擅长用通俗的语言解释复杂概念。
请向高中生解释量子计算是什么，使用类比和日常例子"

为什么好?
- 明确了专业知识水平
- 明确了目标受众
- 明确了表达方式
- AI 会调整语气和内容深度
"""
```

**角色示例：**
```
1. 技术专家
"你是一位资深软件工程师，review 这段代码..."

2. 教师
"你是一位小学数学老师，解释分数的概念..."

3. 客服
"你是一位友好的客服代表，处理客户投诉..."

4. 作家
"你是一位科幻小说家，写一个关于时间旅行的故事..."

5. 顾问
"你是一位商业顾问，分析这个商业模式..."
```

## 🎯 高级 Prompt 技巧

### 1. Zero-shot Prompting

**定义：**
不给任何例子，直接提问

```python
"""
示例:

Prompt:
"将以下英文翻译成中文: Hello, how are you?"

Output:
"你好，你好吗？"

适用场景:
- 简单任务
- 模型已经掌握的技能
- 快速测试
"""
```

### 2. One-shot Prompting

**定义：**
给一个例子

```python
"""
示例:

Prompt:
"""
例子:
输入: "happy"
输出: "开心的"

现在翻译: sad
"""

Output: "悲伤的"

优势:
- 展示了期望的格式
- 提高了准确性
- 仍然很简单
"""
```

### 3. Few-shot Prompting ⭐强大技巧

**定义：**
给多个例子，让模型学习模式

```python
"""
示例:

Prompt:
"""
情感分析任务:

文本: "这部电影太棒了!"
情感: 正面

文本: "服务很差，不会再来了"
情感: 负面

文本: "产品质量一般般"
情感: 中性

文本: "这个餐厅的食物真的很难吃"
情感:
"""

Output: "负面"

原理:
- 模型从例子中学习模式
- 无需额外训练
- In-context Learning

关键:
- 例子要有代表性
- 覆盖不同情况
- 格式一致
"""
```

**Few-shot 的最佳实践：**
```python
"""
1. 例子数量
   - 通常 3-5 个
   - 太多会超出上下文窗口
   - 太少可能不够

2. 例子质量
   - 清晰准确
   - 覆盖边界情况
   - 避免歧义

3. 例子顺序
   - 从简单到复杂
   - 或者随机排列
   - 避免模式化

4. 多样性
   - 不同的输入类型
   - 不同的输出类别
   - 全面覆盖
"""

# 示例: 分类任务
prompt = """
分类以下新闻:

标题: "苹果公司发布新款 iPhone"
类别: 科技

标题: "世界杯决赛今晚举行"
类别: 体育

标题: "股市今日大幅上涨"
类别: 财经

标题: "新电影票房破纪录"
类别:
"""
# Output: "娱乐"
```

### 4. Chain-of-Thought (CoT) ⭐⭐革命性技巧

**定义：**
让模型展示推理过程

```python
"""
传统 prompt:

问题: "小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个?"
答案: 6

Chain-of-Thought prompt:

问题: "小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个?
让我们一步步思考:"

答案:
"1. 开始有 5 个苹果
2. 吃了 2 个，剩下 5 - 2 = 3 个
3. 又买了 3 个，现在有 3 + 3 = 6 个
答案: 6 个"

效果:
- 显著提升复杂推理任务
- 减少错误
- 更容易调试
"""
```

**CoT 的威力：**
```
GSM8K (数学推理基准):

Without CoT:
- GPT-3: 18% 准确率

With CoT:
- GPT-3: 57% 准确率

提升: 3 倍!

原因:
- 分解复杂问题
- 逐步推理
- 减少跳跃错误
- 更像人类思维
```

**CoT 变体：**

#### a) Zero-shot CoT
```python
"""
神奇的方法:

Prompt:
"问题: xxx
让我们一步步思考"

只需加上"让我们一步步思考"
就能触发 CoT!

原理:
- 激活模型的推理能力
- 无需提供例子
- 简单有效
"""
```

#### b) Self-Consistency
```python
"""
多次采样，投票决定

步骤:
1. 用 CoT 生成多个推理路径
2. 得到多个答案
3. 选择出现最多的答案

示例:
路径1: ... → 答案: 6
路径2: ... → 答案: 6
路径3: ... → 答案: 7

最终答案: 6 (多数票)

优势:
- 提高可靠性
- 减少偶然错误
"""
```

### 5. Role Prompting (角色扮演)

```python
"""
深入的角色设定:

Prompt:
"""
你是一位经验丰富的 Python 程序员，有 10 年开发经验。
你的编码风格:
- 遵循 PEP 8 规范
- 注重代码可读性
- 喜欢使用 Pythonic 写法
- 重视错误处理

请 review 以下代码，指出问题并提供改进建议:

def calculate_sum(numbers):
    total = 0
    for i in range(len(numbers)):
        total = total + numbers[i]
    return total
"""

Output:
"""
代码审查意见:

问题:
1. 使用了 C 风格的循环，不够 Pythonic
2. 缺少类型注解
3. 没有文档字符串
4. 没有输入验证

改进版本:
def calculate_sum(numbers: list[float]) -> float:
    '''计算数字列表的总和'''
    if not numbers:
        return 0
    return sum(numbers)

改进说明:
- 使用内置 sum() 函数
- 添加类型注解
- 添加文档字符串
- 处理空列表情况
"""
"""
```

### 6. Instruction Prompting

```python
"""
清晰的指令结构:

Template:
[任务描述]
[输入数据]
[输出要求]
[约束条件]

示例:
"""
任务: 从文本中提取关键信息

输入:
"Apple Inc. 成立于 1976 年，由 Steve Jobs、
Steve Wozniak 和 Ronald Wayne 共同创立。
总部位于美国加利福尼亚州库比蒂诺。"

要求:
- 提取: 公司名、成立年份、创始人、总部
- 格式: JSON

约束:
- 只基于提供的文本
- 不要添加额外信息
- 保持原文拼写
"""

Output:
{
  "company": "Apple Inc.",
  "founded": 1976,
  "founders": ["Steve Jobs", "Steve Wozniak", "Ronald Wayne"],
  "headquarters": "库比蒂诺, 加利福尼亚州, 美国"
}
"""
```

## 🔧 Prompt 优化技巧

### 1. 迭代优化

```python
"""
Prompt 开发流程:

第 1 版: 初始版本
prompt_v1 = "总结这篇文章"

第 2 版: 增加细节
prompt_v2 = "用 100 字总结这篇文章的主要观点"

第 3 版: 指定格式
prompt_v3 = "用 3 个 bullet points 总结这篇文章的主要观点，
每个 point 不超过 30 字"

第 4 版: 添加示例
prompt_v4 = """
示例:
原文: [长文章]
总结:
• 观点1
• 观点2
• 观点3

现在总结:
[新文章]
"""

持续改进:
- 测试不同版本
- 收集反馈
- 不断优化
"""
```

### 2. 分隔符使用

```python
"""
使用分隔符清晰区分不同部分:

Prompt:
"""
请分析以下评论的情感:

=== 评论开始 ===
这个产品真的太棒了！质量超出预期，
物流也很快。强烈推荐给大家！
=== 评论结束 ===

请按照以下格式输出:
- 情感: [正面/负面/中性]
- 置信度: [0-1]
- 关键词: [提取 3-5 个关键词]
"""

常用分隔符:
- === ... ===
- """ ... """
- --- ... ---
- <<< ... >>>
- XML 标签: <text>...</text>

优势:
- 清晰区分指令和数据
- 避免混淆
- 提高解析准确性
"""
```

### 3. 负向提示 (Negative Prompting)

```python
"""
告诉模型不要做什么:

Prompt:
"""
写一段产品介绍:

要求:
✓ 突出产品优势
✓ 使用积极语言
✓ 包含具体数据

禁止:
✗ 不要使用夸张词汇 (如"最好"、"完美")
✗ 不要编造数据
✗ 不要贬低竞争对手
✗ 不要超过 200 字
"""

应用场景:
- 内容审核
- 风格控制
- 避免偏见
- 确保安全
"""
```

### 4. 思维框架 (Thinking Frameworks)

```python
"""
提供思考框架:

Prompt:
"""
分析这个商业决策，使用 SWOT 框架:

决策: 公司是否应该进入电动汽车市场?

请从以下角度分析:
S (Strengths): 优势
W (Weaknesses): 劣势
O (Opportunities): 机会
T (Threats): 威胁

最后给出建议。
"""

常用框架:
- SWOT: 优势、劣势、机会、威胁
- 5W1H: What, Why, When, Where, Who, How
- Pros/Cons: 利弊分析
- STAR: Situation, Task, Action, Result
- PDCA: Plan, Do, Check, Act
"""
```

## 🎓 最佳实践总结

### DO's ✅

1. **具体明确**
   - 详细说明需求
   - 提供足够上下文
   - 指定期望格式

2. **结构化**
   - 使用分隔符
   - 清晰的段落
   - 逻辑顺序

3. **提供示例**
   - Few-shot learning
   - 展示期望输出
   - 覆盖边界情况

4. **迭代优化**
   - 测试不同版本
   - 收集反馈
   - 持续改进

5. **设定角色**
   - 明确专业背景
   - 指定目标受众
   - 调整语气风格

### DON'Ts ❌

1. **不要模糊**
   - 避免歧义
   - 不要假设 AI 知道你的想法

2. **不要一次性太复杂**
   - 分解复杂任务
   - 逐步构建

3. **不要忽略测试**
   - 多场景测试
   - 边界情况验证

4. **不要一成不变**
   - 根据结果调整
   - 适应不同模型

5. **不要忘记约束**
   - 长度限制
   - 格式要求
   - 安全考虑
