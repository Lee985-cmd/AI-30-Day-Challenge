# Day24-Q1 - 文本生成是什么？

## 🤔 文本生成的本质

### 说人话版本

想象一下这个场景：

```
你给 AI 一个开头:
"床前明月光"

AI 接着写:
"疑是地上霜。举头望明月，低头思故乡。"

这就是文本生成!
- 输入：一些提示 (prompt)
- 输出：连贯的文章/诗歌/故事

就像接龙游戏:
你说前半句，AI 接后半句
而且接得合情合理、文采飞扬
```

**文本生成能做什么？**

1. **创意写作**
   - 写诗、写小说
   - 写歌词、写剧本
   - 广告文案

2. **实用写作**
   - 邮件回复
   - 工作报告
   - 新闻稿

3. **代码生成**
   - GitHub Copilot
   - 根据注释写代码
   - 自动补全

4. **对话系统**
   - 智能客服
   - 聊天机器人
   - 心理陪伴

5. **内容创作**
   - 自媒体文章
   - 营销文案
   - 产品描述

## 📜 文本生成的演进历程

### 第一代：基于规则 (1980s)

```python
"""
思路：
- 专家编写大量规则
- "如果...那么..."的逻辑

例子：天气报告生成

if 温度 > 30:
    输出："今天很热"
elif 温度 > 20:
    输出："今天温暖"
else:
    输出："今天凉爽"

缺点:
❌ 需要人工编写规则 (累)
❌ 覆盖不了所有情况 (死板)
❌ 生成的文本生硬 (不自然)
"""
```

**真实案例：**
```
早期聊天机器人 ELIZA (1966):
用户: "我心情不好"
ELIZA: "为什么你心情不好？"

原理：关键词匹配 + 模板填充
- 检测到"心情" → 使用关心模板
- 检测到"问题" → 使用询问模板

局限：
- 没有真正理解
- 容易露馅
- 无法处理复杂对话
```

### 第二代：统计模型 (1990s-2000s)

```python
"""
思路：
- 从大量文本中学习概率
- N-gram 模型

N-gram 原理:
P(下一个词 | 前面n-1个词)

例子 (Bigram, n=2):
P("苹果" | "吃") = 吃苹果的次數 / 吃的总次数

训练:
统计语料库中所有词对的共现频率

生成:
根据概率选择下一个词
"""
```

**优缺点分析：**

✅ **优点:**
- 自动学习，无需人工规则
- 能处理更多样化的输入
- 基于真实数据

❌ **缺点:**
- 只能捕捉短距离依赖
- 数据稀疏问题
- 生成的文本缺乏连贯性
- 无法理解语义

**示例问题：**
```
句子: "我喜欢吃苹果，因为_____"

Bigram 模型可能生成:
- "因为它们" (语法正确，但没说完)
- "因为今天" (不相关)
- "因为红色" (逻辑不通)

原因:
- 只看前一个词"因为"
- 看不到"苹果"、"喜欢"等关键信息
```

### 第三代：RNN/LSTM (2010s)

```python
"""
思路：
- 循环神经网络
- 逐个处理序列
- 维护隐藏状态

RNN 工作原理:

h_t = f(h_{t-1}, x_t)
输出: y_t = g(h_t)

h_t: t 时刻的隐藏状态
x_t: t 时刻的输入
y_t: t 时刻的输出

LSTM 改进:
- 遗忘门：决定忘记什么
- 输入门：决定记住什么
- 输出门：决定输出什么
"""
```

**优势:**
✅ 能捕捉长距离依赖
✅ 理解上下文
✅ 生成更连贯的文本

**局限:**
❌ 串行计算，训练慢
❌ 梯度消失/爆炸
❌ 难以并行化
❌ 长期记忆仍有问题

**实际应用：**
```
Google Translate (2016):
- 使用 LSTM Encoder-Decoder
- 翻译质量大幅提升
- 但仍有限制

限制:
- 长句子翻译差
- 训练时间长
- 需要大量数据
```

### 第四代：Transformer/GPT (2018+)

```python
"""
思路：
- Self-Attention 机制
- 并行化处理
- 大规模预训练

Transformer 优势:
✓ 同时看到整个序列
✓ 捕捉任意距离的依赖
✓ 高效并行训练
✓ 可扩展到超大规模

GPT 创新:
✓ Decoder-only 架构
✓ 因果语言建模
✓ 自回归生成
✓ Few-shot Learning
"""
```

**革命性突破:**

1. **质量飞跃**
   ```
   GPT-2 (2019):
   - 能写 coherent 的文章
   - 基本的逻辑推理
   - 多风格写作
   
   GPT-3 (2020):
   - 1750亿参数
   - Few-shot Learning
   - 接近人类水平
   
   GPT-4 (2023):
   - 多模态理解
   - 复杂推理
   - 专业领域应用
   ```

2. **应用爆发**
   - ChatGPT: 对话助手
   - GitHub Copilot: 代码生成
   - DALL-E: 图像生成
   - Midjourney: 艺术创作

3. **范式转变**
   ```
   传统 AI:
   - 针对特定任务设计
   - 需要大量标注数据
   - 泛化能力弱
   
   GPT 时代:
   - 通用基础模型
   - 少量示例即可
   - 强大的泛化能力
   ```

## 🎯 文本生成的核心任务

### 1. 语言建模 (Language Modeling)

**定义：**
预测序列中下一个词的概率

**公式：**
```
P(w_1, w_2, ..., w_n) = Π P(w_i | w_1, ..., w_{i-1})
```

**应用：**
- 输入法自动补全
- 拼写检查
- 文本生成基础

### 2. 条件文本生成

**定义：**
给定条件（提示），生成相关文本

**类型：**
```
1. 文本续写
输入: "从前有座山"
输出: "山里有个庙..."

2. 翻译
输入: "Hello" (英文)
输出: "你好" (中文)

3. 摘要
输入: 长文章
输出: 简短摘要

4. 问答
输入: 问题 + 文档
输出: 答案
```

### 3. 可控文本生成

**定义：**
控制生成文本的属性

**控制维度：**
- 风格：正式/随意
- 情感：正面/负面
- 主题：体育/科技
- 长度：短/中/长
- 复杂度：简单/专业

**实现方法：**
```python
"""
1. Prompt 控制
"用正式的语言写一封商务邮件"

2. 条件变量
添加 style embedding

3. 解码策略
调整 temperature, top-k 等

4. 后处理
过滤、重排序
"""
```

## 💡 文本生成的评估

### 自动评估指标

#### 1. Perplexity (困惑度)

**定义：**
衡量模型预测的不确定性

**公式：**
```
Perplexity = exp(-1/N * Σ log P(w_i))
```

**解释：**
- 越低越好
- 表示模型更有把握
- GPT-3: ~20
- 人类: ~13

#### 2. BLEU Score

**用途：**
机器翻译评估

**原理：**
比较生成文本和参考文本的 n-gram 重叠

**范围：**
0-1，越高越好

#### 3. ROUGE Score

**用途：**
文本摘要评估

**类型：**
- ROUGE-N: n-gram 重叠
- ROUGE-L: 最长公共子序列

### 人工评估

**评估维度：**

1. **流畅性 (Fluency)**
   - 语法正确
   - 表达自然
   - 逻辑连贯

2. **相关性 (Relevance)**
   - 与提示相关
   - 主题一致
   - 内容恰当

3. **有用性 (Usefulness)**
   - 信息价值
   - 实用性
   - 帮助程度

4. **创造性 (Creativity)**
   - 新颖性
   - 多样性
   - 想象力

**评估方法：**
```
Likert Scale (1-5分):
1 - 非常差
2 - 较差
3 - 一般
4 - 较好
5 - 非常好

对比评估:
A vs B，哪个更好？
```

输出:

优势:
✓ 快速生成初稿
✓ 提供灵感
✓ 节省时间

注意:
- 需要人工审核
- 事实核查
- 风格调整
```

优势:
✓ 24/7 服务

```
